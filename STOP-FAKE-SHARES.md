# How to stop the FAKE "Shares" number on palikalive.com

## What was found (diagnosis)

On every news article, next to the share icons (Facebook / Messenger /
WhatsApp / X), the theme prints a big number with the word **"Shares"**.

That number is **not real** and it is **not coming from ShareThis**:

- The number changes on its own. The same article was loaded a few minutes
  apart (cache bypassed) and showed **74, then 350, 360, 380, 390, 410, 420,
  440, 450** — every uncached page load adds about **+10**, and Google,
  Facebook, WhatsApp and other crawlers/bots trigger those loads too.
- No clicking of any share button is required for the number to grow, and
  real shares are never counted.
- It is printed by the **active theme `palikalive` (internal name
  "nepallive", by Saas Tech Nepal)** in the markup
  `.share-total > span` + the label `.shares`, which appears up to three
  times on an article page (sticky header, normal header, desktop left
  share rail).
- The **ShareThis Share Buttons plugin (v2.3.12) is installed** and an empty
  `<div class="sharethis-inline-share-buttons">` block is present at the top
  of article bodies, but the visible fake number is the theme's
  `.share-total`, not ShareThis.
- The Messenger icon is also broken — its link literally contains
  `app_id=YOUR_FB_APP_ID` (a placeholder the theme developer never replaced).
- Someone already tried `.share-total { display:none !important; }` in the
  theme-root `style.css`, but it does nothing because **that stylesheet is
  not loaded on the website** — the site loads
  `wp-content/themes/palikalive/assets/css/style.css` instead.

There are three levels of fix. **Do Step 1 now (2 minutes, no risk), and
ask your developer/host to do Steps 2–4 to remove the problem properly.**

---

## STEP 1 — Hide the fake number immediately (no code editing)

1. Log in to WordPress admin (`/wp-admin`).
2. Go to **Appearance → Customize → Additional CSS**.
3. Paste the contents of **[`fixes/hide-fake-share-counts.css`](fixes/hide-fake-share-counts.css)**
   into the box and click **Publish**.
4. **Purge cache**: Cloudflare dashboard → Caching → Configuration →
   **Purge Everything**, and purge any WordPress cache plugin
   (LiteSpeed Cache / WP Super Cache / W3 Total Cache).

The number will disappear on phones and desktops. The fake value may still
be written in the background — Step 2 stops that too.

---

## STEP 2 — Remove the fake counter from the theme (proper fix)

The number is generated by PHP in the theme, so the real fix is to delete
that code.

1. In WP admin go to **Appearance → Theme File Editor**
   (or edit files with cPanel File Manager / FTP under
   `wp-content/themes/palikalive/`).
2. Open **`single.php`** and any file it includes for the article header
   (look in folders like `template-parts/`, `template/`, `inc/`, or
   partials named `single-*`, `post-header`, `share`).
3. Use your browser's find (Ctrl+F) and search every theme file for:
   - `share-total`
   - `Shares`
   - `share_count`, `_share`, `shares`, `update_post_meta`
4. You will find a block similar to:

   ```php
   <div class="share-total">
       <span><?php echo ... /* number */ ...; ?></span>
       <span class="shares">Shares</span>
   </div>
   ```

   **Delete that block.**
5. Nearby (often in the same file or in `functions.php` / an `inc/*.php`
   file) there is code that inflates a number on page load, e.g. something
   shaped like:

   ```php
   $shares = (int) get_post_meta( $post->ID, 'share_count', true );
   $shares += 10;                       // or rand(...) / * 10 etc.
   update_post_meta( $post->ID, 'share_count', $shares );
   ```

   **Delete those lines (and the function they belong to if it does nothing
   else).** Note the exact meta key (the string inside `get_post_meta`,
   e.g. `share_count`) — you need it for Step 4.
6. While editing, also delete/repair the Messenger anchor that contains
   `app_id=YOUR_FB_APP_ID` (it cannot work as-is). Either remove the
   Messenger button or replace it with a real Facebook App ID.
7. Save, then purge cache again (Step 1.4).

Best practice: make these changes in a **child theme** so a theme update
cannot bring the fake counter back.

### Alternative without editing PHP: the must-use plugin

If editing templates is not possible, copy
[`fixes/mu-stop-fake-shares.php`](fixes/mu-stop-fake-shares.php) to
`wp-content/mu-plugins/stop-fake-shares.php` (create the `mu-plugins`
folder if missing). It:

- automatically removes the leftover ShareThis block from article bodies
  when the ShareThis plugin is not active;
- once you know the meta key from Step 5/Step 4, set
  `PALIKA_FAKE_SHARE_META_KEY` inside the file and the counter is frozen at
  0 and stops being inflated.

(Step 1 CSS is still needed to hide the number itself when using the
plugin.)

## STEP 3 — Decide what to do with ShareThis

Two things are tangled together:

- **The theme's own share icons** (the Facebook/WhatsApp/X links with the
  fake number) — handled in Steps 1–2.
- **The ShareThis plugin's own block** — the empty
  `sharethis-inline-share-buttons` div at the top of every article.

Choose one:

- **You do not want ShareThis:** go to **Plugins → Installed Plugins**,
  **deactivate** and then **delete "ShareThis Share Buttons"**. Then run
  the cleanup in Step 4 to remove the blocks already stored in old
  articles.
- **You want real ShareThis buttons:** keep the plugin, open its settings
  (**Settings → ShareThis**) and make sure it is connected with your
  ShareThis property ID; the inline buttons will then render inside those
  divs. Be aware ShareThis' own count bubble (`.st-total`) also counts
  clicks/attempts (and bot traffic), not completed shares — if you do not
  trust it, enable the optional `.st-total` rule in the CSS from Step 1.

Do not leave the plugin deactivated while the divs remain in every
article: it leaves empty space and confusing markup.

---

## STEP 4 — Clean up the old fake values in the database

Use [`fixes/cleanup.sql`](fixes/cleanup.sql) (it contains preview queries,
the exact removal statements, and safer WP-CLI equivalents). Summary:

1. **Back up the database first.**
2. Remove the stored ShareThis divs from article bodies (Step B in the
   file).
3. Identify the fake-counter meta key on a known article, e.g. post
   `130321` (Step C).
4. Delete or zero that meta key on all posts (Step D).
5. Purge Cloudflare and the WordPress cache.

---

## STEP 5 (optional) — Show only real numbers

If you want to display genuine share/interest counts:

- Real **Facebook** share counts now require a Facebook App and the Graph
  API (or a service like SharedCount); they cannot be read anonymously
  anymore.
- Real **post views** are best counted with a reputable plugin such as
  **Post Views Counter** or **WP-PostViews** (which exclude bots/crawlers),
  labelled **"Views"**, not "Shares".
- Never label a click or a pageview as a "Share" — it misleads readers and
  advertisers and, for a registered news outlet (DIB Reg. No. 3996/2079-80),
  is a credibility risk.

## STEP 6 — Show a REAL share count instead

Hiding the fake number (Steps 1–2) leaves no number at all. Facebook,
WhatsApp and X no longer publish completed-share totals publicly, so the
only universally honest number a site can show is **how many times real
visitors clicked its own share buttons**. The plugin
[`fixes/palika-real-shares.php`](fixes/palika-real-shares.php) counts those
clicks server-side and displays the verified total in the theme's existing
"Shares" spot.

Why it cannot be faked:

- counting only happens inside a real browser click handler — crawlers,
  Facebook/Google/WhatsApp bots and simple page refreshes never trigger it;
- the same visitor + network + article is counted at most once per 6 hours
  (uses the Cloudflare visitor IP);
- the number is stored in post meta (`_palika_real_shares`) and read over
  the REST API after page load, so Cloudflare/cached pages always show the
  current value;
- counts start at 0 from activation — the old inflated figures were
  fabricated and cannot be converted into real data.

Installation:

1. Copy `fixes/palika-real-shares.php` to
   `wp-content/mu-plugins/palika-real-shares.php` (create the `mu-plugins`
   folder if needed). It runs automatically; no activation click.
2. In **Appearance → Customize → Additional CSS**, remove the earlier
   "hide everything" CSS and paste
   [`fixes/real-share-counts.css`](fixes/real-share-counts.css) instead
   (it hides the fake value only until the real one loads).
3. Purge Cloudflare + the WordPress cache and open an article. Click a
   share button — the count increases by 1; reloading the page keeps the
   real value (a second click within 6 hours from the same visitor is not
   double-counted).
4. **Optional official Facebook numbers:** create a free Facebook App and
   add `define('PALIKA_FB_GRAPH_TOKEN', 'APP_ID|APP_SECRET');` to
   `wp-config.php`. Facebook's official `engagement.share_count` is then
   added to the total (cached 2 hours). WhatsApp and X have no public
   count API for anyone.

## STEP 7 — Confirmed on live site: theme multiplies the real count × 5

Verified September 2026: the theme stores a real-ish base number but
prints it **× 5** and adds fake views on every page load (article that
should show ~120 rendered 600 → 630 → 650 as the page was reloaded).

Use [`fixes/palika-fix-share-count.php`](fixes/palika-fix-share-count.php)
(v2.0): a small server-side plugin (no JS/REST) that

1. divides every `.share-total` number back to the real value in the page
   HTML;
2. auto-detects the counter's post-meta key (visible in page source as
   `<!-- palika share key detected: ... -->` on the first uncached load)
   and then blocks the fake per-view increments;
3. needs no configuration; divisor is the `PALIKA_SHARE_DIVISOR` constant
   (5). Installs as a mu-plugin, a Code Snippets snippet, or inside
   functions.php — instructions are in the file header.
